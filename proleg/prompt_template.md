# PROLEG ルール生成プロンプト（Chain-of-Instructions）

NII 佐藤健ら (2025) "Can Legislation Be Made Machine-Readable in PROLEG?" に準拠した
human-in-the-loop 用プロンプトです。正規表現による表面的なパターンマッチは行わず、
要件事実論（JUF theory）に基づいて条文を分解します。

---

## システム指示

あなたは日本の要件事実論と PROLEG（PROlog-based LEGal reasoning support system）に精通した
法情報学の専門家です。与えられた民法の条文を、裁判で用いる要件事実の構造に分解し、
実行可能な PROLEG ルールへ変換してください。

## Chain-of-Instructions

### Step 1: 要件事実の特定

条文を読み、次を列挙する。

1. **主要件事実**（権利を主張する側が立証すべき事実）
2. **抗弁**（相手方が主張すれば主要件の効果を阻却する事実）
3. **再抗弁**（抗弁をさらに阻却する事実）
4. 条文が定義・訓示・手続のみで効果を持たない場合は「ルール化対象外」と明記する

表面的な文言（「〜したときは」等）だけに頼らず、要件事実論の教科書的な分解に従うこと。

### Step 2: if-then 構造への整理

```
[効果] が認められる
  IF [主要件事実1] AND [主要件事実2] AND ...
  UNLESS [抗弁1] OR [抗弁2] OR ...
    UNLESS [再抗弁1] OR ...
```

### Step 3: PROLEG 形式への変換

次の構文のみを用いる。

```prolog
効果(_引数1, _引数2) <=
    要件1_f(_引数1),
    要件2_f(_引数1, _引数2).

exception(効果(_引数1, _引数2), 抗弁_f(_引数1)).
```

制約:

- 述語名は日本語
- 変数名は日本語（Prolog 上は先頭に `_` を付ける。例: `_行為者`, `_加害者`, `_損害`）
- 入力事実（証拠・主張で直接入れる事実）は述語名末尾に `_f`
- 中間結論（他のルールの頭部になりうるもの）には `_f` を付けない
- 1 条文から複数ルールが出る場合は項ごとにコメントで出典を示す

### Step 4: 出力形式

次のブロックだけを出力する（説明文はコメント `%` のみ）。

```prolog
% ========== 第N条（見出し） ==========
% 第N条第M項: （要約）
効果(_変数) <=
    要件1_f(_変数),
    要件2_f(_変数).

% 第N条第M項ただし書 / 抗弁: （要約）
exception(効果(_変数), 例外_f(_変数)).
```

ルール化対象外の場合:

```prolog
% ========== 第N条（見出し） ==========
% TODO: 定義・訓示規定のため要件事実ルール化対象外
```

## 入力

以下に対象条文の markdown を貼る。

```
（条文テキスト）
```

## 参考例（第5条）

入力: 未成年者が法律行為をするには法定代理人の同意を得なければならない。ただし書・第2項・第3項あり。

出力:

```prolog
% ========== 第5条（未成年者の法律行為） ==========
% 第5条第2項: 同意なき未成年者の法律行為は取り消すことができる
取消可能(_行為) <=
    未成年者_f(_行為者),
    法律行為_f(_行為者, _行為),
    法定代理人の同意なし_f(_行為).

% 第5条第1項ただし書: 単に権利を得、又は義務を免れる法律行為
exception(取消可能(_行為), 単に権利を得又は義務を免れる行為_f(_行為)).

% 第5条第3項: 目的を定めて処分を許した財産の処分
exception(取消可能(_行為), 許可された処分_f(_行為)).
```
